### 깃허브 제작

해당글은 깃허브 블로그 호스팅 과정중 전체적인 방향을 요약했고 과정중 꽤나 중요했던 일들을 적고자 합니다. 이제는 놓치지 않도록..

### 사전 준비

- ruby 설치

설치이전에 루비를 웹에서 다운받을때 버전 잘 보고 설치해야합니다..안정적인 릴리스 버전으로 해야 예상치 않은 오류가 발생하지 않습니다..

- Node.js 설치

이것도 웹상에서 바로 다운이 가능한데 설치 안하면 이후 로컬 서버 열때 문제가 생깁니다. 만약 빌드 과정에서 문제가 생긴 이후에 다운받고 해결하려면 아래 커맨드를 입력하면됩니다.

``` bash
npm install  //읜존성 패키지를 설치
npm run build  //배포 가능한 상태로 빌드
```

### 테마 설치

저는 Chipry테마를 fork하는 방식으로 작업하였는데, 해당 과정중 무난하게 저장소 이름을 지정하고 만들면되는데, 꼭 브랜치 이름을 변경해줘야합니다.(초기화 과정중 오류발생생)

Setting -> General -> Rename this branch에서

```
master -> main
```

### 테마 초기화

저장소로 fork한 테마를 clone 한 후 해당 폴더에 들어가 초기화를 하는데 window에선 아래의 초기화 커맨드를 사용하지 못한다.

```
tools/init.sh
```
이를 일일히 문서를 지우는 것과 GIt 또는 WSL 파워쉘 등 여러 방법이 있는데 모두 사용해봤을때 가장 편했던 것은 WSL 리눅스를 이용해서 초기화를 하는 것이 가장 안전하고 좋은 것 같습니다.

### git push

로컬에 대한 문서가 잘 마무리되고 커밋을 하게 될텐데 commit 내용도 무리하게 작성하지 않아야 오류가 생기지 않습니다.(알잘딱하게..)

```
git add -A
git commit -m "test"
git push
```

### 번들 설치

번들이나 지킬에 대한 커맨드를 설치할때 꼭 블로그 저장소로 위치시킨 상태에서 실해야합니다.

```
gem install bundler
gem install jekyll
```

### --layout: home # index page -- 오류

대게 모두가 해당 오류때문에 골치가 아픈데 이는 십중팔구 브랜치 과정에 문제가 있는겁니다. 제대로 브랜치 이름을 바꾸고 루비 버전도 잘 맞게 한다면 크게 오류가 나지 않는다.

-> 이후에 해결하는 방법이 있긴한데 복잡하니 저장소를 삭제하고 서순에 잘 맞게 위 오류를 고려하며 진행하는 것을 추천합니다.
