### 페이지 교체를 알기전..

페이지 교체를 알기전 우리가 왜 페이지를 교체하고 이에 대한 알고리즘을 배우는지 알아야한다. 그래서 가상메모리와 요구 페이징만 간단히 복습해보자.

---

### 가상 메모리

가상 메모리의 존재이유는 무엇일까? 그것은 물리 메모리의 한계로부터 비롯된다.

```
1.물리 메모리 보다 큰 크기의 프로세스는 실행될 수 없다!
2.동시 수행되는 프로세스들의 크기의 총합은 물리 메모리보다 클 수 없다!
```
위 같은 조건들 때문에 메모리 적재가 쉽지 않았는데 이를 해결하는 방법이 가상메모리, 즉 보조저장장치를 사용함에 있다. 

> 가상 메모리 : 물리적인 메모리(주기억장치, RAM)의 크기보다 더 큰 용량의 메모리를 사용하는 것처럼 실행할 수 있게 해주는 메모리 관리 기법

실행을 위한 프로세스의 일부만 메모리에 할당하고 메모리 부족시 일부 내용을 스왑 영역으로 옮겨 빈 영역을 확보한다. 다중 프로그래밍 정도를 높이고, CPU 이용율을 향상시킨다

하지만 가상 메모리에 대한 관련 문제들도 존재한다.

---

### 요구 페이징

이전 페이징은 <u>'메모리를 같은 크기로 나눠서 조각조각 저장하는 기법'</u> 이라고 배웠는데 요구 페이징도 비슷하다.

>요구 페이징 : 필요한 페이지들만 물리 메모리에 적재하는 방법

결론적으로 실행중에 필요할때 적재된다. 사용되지 않으면 페이지는 적재되지 않는데 <u>만약 메모리가 부족할때 메모리를 비우고 페이지를 저장하는 영역</u>을 스왑 영역이라 한다.

가상 메모리에서 페이지 테이블은 2개로 나눠지는데 

>valid/presence bit : 해당 페이지가 물리 메모리에 있는지 여부 

>modified bit(dirty bit) : 해당 페이지가 수정되었는 여부

해당 페이지가 프레임에 적재된 이우에 수정되었으면 스왑 아웃할때 스왑 영역에 저장할 필요가 있음

---

### 페이지 부재

> 페이지 부재 : 프로그램 실행 중, 코드(예: 함수나 명령어)가 있는 페이지가 아직 메모리에 올라와 있지 않을 때 발생하는 페이지 부재 현상

---

### 스레싱

> 스레싱 : 프로세스가 실제 작업보다 페이지 교체 작업에 더 많은 시간을 소비하는 현상

결론적으로 가상 메모리 관리 실패로 인해 지연되고 있는 것이다. 대게 프레임 부족으로 프로세스가 작업을 수행하는데 필요한 만큼의 프레임을 할당받지 못해 페이지 부재가 일어난다.

다중 프로그래밍 정도는 높이면(가상 메모리 사용) CPU 이용률은 증가하지만 어느 임계점에 다다르면 스레싱이 발생하여 CPU 이용률이 급격히 하락한다.

가상 메모리에 대한 간략한 개념만 짚어봤는데 우리는 여기서 요구 페이징을을 더 깊게 공부해보자 비효율적인 요구 페이징은 페이지 부재를 증가시키고, 결국 스레싱을 유발한다.

---

### 요구 페이징 알고리즘

요구 페이징을 적재하는 알고리즘은 2가지가 있다.

>프레임 할당 알고리즘 : 프로세스 당 할당할 frame의 개수를 결정

아직 메모리에 올라와 있지 않는 현상, 페이지 부재를 줄일 수 있다.

> 페이지 교체 알고리즘 : 페이지 부재가 발생했으나 빈 프레임이 없으면 비울 프레임을 결정

자주 쓰이지 않는 페이지가 담긴 프레임을 고르고, 필요한 페이지는 교체되지 않도록 한다.

위와 같이 페이지 부재에 대한 해결이나 예방이 있는데, 조건도 있다.

- 각 프로세스 마다 실행에 필요한 최소 페이지 프레임 수가 확보

- 한 명령어를 실행하려면 명령어가 필요로 하는 모든 페이지가 메모리에 미리 있어야 한다.

<u>결론적으로 할당한 적정 프레임수가 부족하면 교체 작업이 빈번해 스레싱이 발생할 것이고 너무 과도한 프레임 할당은 시스템 효율을 떨어뜨린다.</u>

---

### 프레임 할당 알고리즘

프레임 할당 알고리즘은 3가지가 있다. 프레임 당 할당할 프레임 개수를 결정하는 방법이다.

> 균등 할당 : 모든 프로세스들에게 같은 수의 프레임을 할당 -> 작은 프로세스는 과할당 발생

> 비례 할당 : 각 프로세스의 크기에 비례하여 할당

> 우선순위 할당 : 각 프로세스의 우선순위에 따라 할당

--- 

### 페이지 교체 알고리즘

페이지 교체도 2가지로 나뉘는데, 지역교체와 전역 교체다.

> 지역 교체 : 자기 프로세스가 배정받은 프레임 안에서만 교체한다.

프레임 개수는 고저오디고 내가 쓴 것 중에서 덜 쓰는 것을 골라서 바꾼다. 다른 프로세스의 영향은 없지만 효율이 떨어질 수 있다. 왜냐하면 어떤 프로세는 많은 프레임을 가지고 누구는 프레임이 부족해 페이지 부재가 일어나기 때문.

> 전역 교체 : 시스템 전체의 모든 프레임 중 아무거나 교체 대상이 될 수 있다.

프레임 개수가 유동적이고 다른 프로세스의 프레임도 가져올 수 있다. 어떤 프로세스가 많이 쓰면 다른 프로세스에 대한 성능이 저하되고 페이지 부재가 다른 프로세스에 의해 바뀐다.

결론적으로 <u>지역 교체는 내방 청소, 옆방 물건 건들지 말기. 이고 전역 교체는 전체 기숙사 청소할때 너의 방도 치운다. 이런식이다.</u>

대게 지역 교체는 실시간 시스템 성능 예측이 중요할때 사용되고 전역은 최적화가 중요할 때 사용된다.

| 구분            | 지역 교체(Local) | 전역 교체(Global)     |
| ------------- | ------------ | ----------------- |
| **프레임 교체 범위** | 자기 것만        | 전체 시스템            |
| **프레임 수**     | 고정           | 유동적               |
| **성능 영향**     | 독립적          | 다른 프로세스 영향 받음     |
| **장점**        | 예측 가능, 공정    | 전체 자원 활용 효율 ↑     |
| **단점**        | 비효율적일 수 있음   | 성능 변동성 ↑ (스래싱 위험) |
