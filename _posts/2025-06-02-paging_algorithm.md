### 페이지 교체 알고리즘

페이지 교체 알고리즘이란 페이지 부재가 발생하여 빈 프레임이 없으면 비울 프레임을 결정하는 방식이다.

기존 메모리에는 넣을 공간이 제한되어있기에 기존 페이지 하나를 교체한다.

주어진 메모리 접근 방식은 알고리즘을 적용해 총 페이지 부재수를 기준으로 평가한다.

이제 일괄적인 알고리즘을 알아보자.

---

### FIFO Algorithm

| 항목         | 내용                            |
| ---------- | ----------------------------- |
| **이름**     | FIFO (First-In-First-Out)     |
| **기본 원리**  | 메모리에 가장 먼저 들어온 페이지를 가장 먼저 내보냄 |
| **데이터 구조** | **Queue (선입선출)** 사용           |
| **결정 기준**  | 가장 오래된 page를 교체함 (들어온 순서 기준)  |
| **주요 특징**  | 단순하고 구현이 쉬움                   |

FIFO는 구현이 간단하다. 하지만 최근 사용된 페이지를 고려하지 않기에 비효율적이다. 페이지가 자주 사용되어도 오래전에 들어오면 교체당할 수 있다. 기본적으로 페이지 사용이 단순하고 복잡도를 낮추고 싶을때 사용된다. 페이지 부재를 최소화하는건 조금 힘들다.

---

### Optimal Algorithm(Min 알고리즘)

| 항목         | 내용                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------- |
| **이름**     | Optimal Page Replacement (또는 MIN Algorithm)                                                   |
| **기본 원리**  | 앞으로 가장 오랫동안 **사용되지 않을** 페이지를 교체                                                               |
| **데이터 구조** | 미래 참조 시퀀스를 저장한 배열 또는 리스트<br>(시뮬레이션에서만 사용 가능)                                                  |
| **결정 기준**  | 메모리 내 페이지 중 **가장 나중에 다시 사용될 페이지** 선택                                                          |
| **주요 특징**  | - Page fault 수를 **이론적으로 최소화**함<br>- Belady 제안<br>- 실제 시스템에서는 사용 불가<br>- 다른 알고리즘 성능 비교의 기준선 역할 |

Min 알고리즘은 FIFO와 다르게 앞으로 가장 오랫동안 사용되지 않을 페이지를 찾아 제거하는 방식이다.  최소한의 페이지 부재수를 보장하지만 다소 비현실적이다.

---

### LRU Algorithm

| 항목         | 내용                                                                                            |
| ---------- | --------------------------------------------------------------------------------------------- |
| **이름**     | LRU (Least Recently Used)                                                                     |
| **기본 원리**  | **가장 오랫동안 사용되지 않은 페이지**를 교체함                                                                  |
| **데이터 구조** | **Age Counter**, **Stack**, 또는 **해시 + 리스트** 조합 등 사용                                           |
| **결정 기준**  | 메모리 내 페이지 중 **가장 마지막으로 사용된 시점이 오래된 페이지** 선택                                                   |
| **주요 특징**  | - 일반적으로 좋은 성능<br>- **Belady의 Anomaly 발생 없음**<br>- 구현 복잡도 있음<br>- **TLB 등 하드웨어 지원 시 성능 향상 가능** |

LRU는 가장 오랫동안 사용되지 않은 페이지를 교체하는 알고리즘이다. 중요한건 사용된 시점이기에 이를 추적하기 위해 Age Counter나 스택 해시 등을 사용한다. 이렇기에 다소 구현이 복잡하고 메모리 조작이 발생하기에 지연이 발생하기도 한다.

---

### LRU Approximation Algorithm(LRU 근접 알고리즘)

| 항목         | 내용                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| **이름**     | LRU Approximation Algorithm<br>(예: CLOCK 알고리즘 등)                                                             |
| **기본 원리**  | \*\*정확한 LRU 구현 대신, 참조 비트(Reference Bit)\*\*를 통해 페이지의 **사용 여부만 추정**                                           |
| **데이터 구조** | 각 페이지마다 **Reference Bit**를 할당<br>(일반적으로 비트 배열 or 원형 포인터 큐 사용)                                                |
| **결정 기준**  | 최근 참조되지 않은 페이지를 **1비트 정보 기반으로 식별**하여 교체                                                                      |
| **주요 특징**  | - **LRU의 성능을 근사**함<br>- **정확한 사용 순서는 알 수 없음**<br>- 하드웨어가 LRU 직접 지원하지 못할 때 사용<br>- **CLOCK, NRU 등 다양한 변형 존재** |

LRU를 보완한 알고리즘이다. 구현이 복잡한 것을 참조 비트만을 이용해 사용된 시점을 추정한다. 참조 비트는 각 페이지 마다 할당하고 초기에 os에 의해 리셋된다. 정확한 사용순서는 알지 못하지만 참조 여부는 확인 가능하다.

### CLOCK(2차 기회 알고리즘)

| 항목         | 내용                                                                              |
| ---------- | ------------------------------------------------------------------------------- |
| **이름**     | Second-Chance Algorithm<br>(a.k.a. **Clock Algorithm**, **FINUFO**)             |
| **기본 원리**  | **FIFO 기반**으로 작동하되, 각 페이지의 \*\*참조 비트(Reference Bit)\*\*를 확인하여 교체 여부 결정          |
| **데이터 구조** | \*\*순환 큐 (Circular Queue)\*\*와 **포인터(Pointer)**, 각 페이지에 **Reference Bit (1비트)** |
| **결정 기준**  | 포인터가 가리키는 페이지의 Reference Bit이<br>– `0`: 바로 교체<br>– `1`: 비트 reset하고 다음 페이지 검사    |
| **주요 특징**  | - **LRU를 근사하면서 FIFO처럼 단순**<br>- 구현이 효율적이고 실제 OS에서 널리 사용<br>- 참조 순서를 정확히 알진 못함   |

2차 기회 알고리즘은 FIFO 방식에 LRU 개념을 일부 결합한 방식이다. 기본적으로는 가장 오래된 페이지(FIFO)를 선택하지만, 교체 전에 해당 페이지의 참조 비트를 먼저 확인한다. 페이지 교체가 필요할 때는 포인터가 하나씩 페이지를 가리키며 참조 비트 값을 검사한다.

- 참조 비트가 0이면: 바로 교체 대상이 된다.

- 참조 비트가 1이면: 최근에 사용된 것으로 판단하여 비트를 0으로 초기화하고 한 번 더 기회를 준다.

이 과정을 순환 큐와 포인터를 이용해 반복하며, 마치 시계바늘처럼 동작한다고 해서 "Clock Algorithm"이라고도 불린다. 구현이 간단하면서도 성능이 우수해 실제 운영체제에서 자주 사용된다.

### Counting Algorithm

| 항목         | 내용                                                                                   |
| ---------- | ------------------------------------------------------------------------------------ |
| **이름**     | Counting Algorithms<br>– LFU (Least Frequently Used)<br>– MFU (Most Frequently Used) |
| **기본 원리**  | 각 페이지의 **참조 횟수를 카운팅**하여 교체 대상 선정                                                     |
| **데이터 구조** | 페이지마다 **카운터 변수**를 유지 (배열 또는 해시 맵 등)                                                  |
| **결정 기준**  | - **LFU**: 가장 적게 참조된 페이지를 제거<br>- **MFU**: 가장 많이 참조된 페이지를 제거                         |
| **주요 특징**  | - 사용 패턴을 **통계적으로 분석**해 교체 결정<br>- 오래된 페이지에 대한 보정 필요<br>- 구현 복잡도 높음                   |

Counting Algorithms는 각 페이지가 있는 동안 얼마나 자주 참조 되는지 카운터로 기록한다음 이를 LFU 또는 MFU를 이용해 제거한다. 

- LFU (Least Frequently Used):
- 
참조 횟수가 가장 적은 페이지를 교체 대상으로 삼는다.

→ 자주 참조되지 않은 페이지는 앞으로도 사용할 가능성이 낮다고 판단하는 방식이다.

- MFU (Most Frequently Used):
- 
참조 횟수가 가장 많은 페이지를 제거한다.

→ 자주 참조된 페이지는 이미 충분히 사용되었기 때문에, 앞으로는 사용되지 않을 것이라고 가정한다.

추가적으로 실제 운영체제에서는 거의 사용되지 않는다.
---

### LIFO Algorithm

| 항목         | 내용                                                       |
| ---------- | -------------------------------------------------------- |
| **이름**     | LIFO (Last-In-First-Out)                                 |
| **기본 원리**  | **가장 최근에 적재된 페이지**를 교체함                                  |
| **데이터 구조** | **스택(Stack)** 또는 최근 적재된 페이지 추적용 변수                       |
| **결정 기준**  | 메모리 내 페이지 중 **가장 마지막에 들어온 페이지**를 제거                      |
| **주요 특징**  | - 구현은 매우 단순<br>- 현실성과 성능 모두 낮음<br>- Belady의 모순 발생 가능성 있음 |

스택 구조를 기반하고 구현은 단순하지만 실제 메모리 접근가 어긋하는 경우가 많아 성능이 안좋다. 애초에 계속 참조되는데 불구하고 제거하기 때문에 페이지 부재가 자주 발생하다. 실제 운영체제에서는 거의 사용하지 않는다.

### Random Algorithm

랜덤 알고리즘은 현재 메모리에 적재된 페이지들 중 아무 페이지나 무작위로 선택해 교체하는 방식이다. 성능 보장이 어렵기에 실제 운영체제에서는 거의 사용되지 않는다.

---

| 알고리즘                        | 작동 원리                 | 장점                     | 단점                          | 구현 난이도   | **Belady 현상** | 참고 정보          |
| --------------------------- | --------------------- | ---------------------- | --------------------------- | -------- | ------------- | -------------- |
| **FIFO**<br>(먼저 들어온 순서 제거)  | 가장 오래된 페이지 제거         | 구현이 아주 쉬움              | 성능 낮음, 예외적으로 페이지 교체 더 늘기도 함 | 🔹 쉬움    | ✅ 생김          | 큐 사용           |
| **Optimal**<br>(최적 알고리즘)    | 앞으로 제일 늦게 쓰일 페이지 제거   | 이론상 가장 적은 Page Fault 수 | 실제 구현 불가능 (미래 모름)           | ❌ 사용불가   | ❌ 안 생김        | 기준 비교용 (이론 전용) |
| **LRU**<br>(가장 오래 안 쓴 것 제거) | 최근 사용 기록 따라 제거        | 실제 성능 좋음               | 구현 복잡, 시간·공간 많이 듦           | 🔸 어려움   | ❌ 안 생김        | 스택이나 해시로 구현    |
| **LRU 근사**<br>(예: CLOCK)    | 사용 여부만 1비트로 대충 판단     | LRU보다 구현 쉬움, 성능 무난     | 정확한 순서 파악은 불가능              | 🔸 보통    | ❌ 거의 없음       | CLOCK 알고리즘 등   |
| **CLOCK**<br>(2차 기회 방식)     | 포인터 돌리며 참조 비트 확인      | 구현 쉬우면서 LRU 흉내 가능      | 완전한 LRU는 아님                 | 🔸 보통    | ❌ 거의 없음       | 실제 운영체제 많이 씀   |
| **Counting**<br>(LFU/MFU)   | 참조 횟수 기반 (자주/안 쓰인 순서) | 통계로 판단 가능              | 오래된 카운트 누적되면 오류 날 수 있음      | 🔸 어려움   | ❌ 거의 없음       | 보정 로직 필요       |
| **LIFO**<br>(최근에 넣은 것 제거)   | 가장 마지막에 들어온 페이지 제거    | 구현 단순                  | 성능 매우 나쁨, 실제와 안 맞음          | 🔹 쉬움    | ✅ 생김          | 스택 구조          |
| **Random**<br>(무작위 선택)      | 아무 페이지나 랜덤으로 제거       | 코드 매우 간단               | 결과 들쑥날쑥, 예측 불가              | 🔹 매우 쉬움 | ❌ 안 생김        | 실전보단 실험용       |

위 Belady 현상은 프레임 수를 늘렸는데 오히려 페이지 부재가 발생되는 현상을 의미미
